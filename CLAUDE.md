# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`claude-ide` (plugin name `ide-panes`; names starting with `claude-` are reserved by the validator): an IDE-like interface built *inside* Claude Code as a mod (a plugin of function hooks): panes, bands above the prompt, status line entries, slash commands, tool-call hooks. Not a standalone app: no DOM, no Node, no bundler.

Before writing or debugging hook code, load the `plugin-authoring` skill. It has the current API, the examples and the path to this build's `claude-code.d.ts`.

## Permissions

This is the owner's own Claude Code plugin development repo, and every action in it is authorized: editing any file, running `claude --plugin-dir .`, `claude plugin validate|test`, `tsc`, git (including commit and push), and spawning `claude` subprocesses to test the plugin. `.claude/settings.local.json` allows all tools for this repo.

## Layout

The repo root is the plugin folder:

- `.claude-plugin/plugin.json`: `{ "name": "ide-panes", "version": "...", "description": "...", "types": "./types/index.d.ts" }`
- `hooks/hooks.json`: `{ "modules": ["./register.tsx"] }`
- `hooks/register.tsx`: entry point, `export const register: Register = (on, options) => { ... }`, with `Register` imported from `'claude-code'`. Feature modules export a named `register(on)`, and the entry imports it by name (`import { register as registerExplorer } from './explorer-panel'`). The validator rejects passing `on` through a namespace import (`explorer.register(on)`).
- `types/index.d.ts`: the `$.state` contract. Every value kept in `$.state` must be declared in `interface PluginState` under the plugin name, and `claude plugin validate` enforces this.
- `hooks/**/*.test.ts`: tests run by `claude plugin test`
- `.claude-plugin/types/`: generated by the engine on load (API, tool and MCP typings, `tsconfig.json`). Do not edit it, and keep it out of git.

## Commands

```sh
claude --plugin-dir .                 # run Claude Code with this mod; saving a file hot-reloads it
claude plugin validate .              # manifest, hooks and $.state keys checked against the contract
tsc -p .                              # type-check (needs .claude-plugin/types/, laid down after the first load)
claude plugin test .                  # run all *.test.ts against the real engine
claude --debug --plugin-dir .         # debug log: every hook error and every refused ui.render tree
```

There is no single-test flag; to run one test, narrow the test files or the `test(...)` calls in a file.

## Architecture of a mod

- `on(event, matcher?, hook)` registers a hook. Each hook is `($, e, next)`:
  - `$` is the engine interface (`$.ui`, `$.state`, `$.store`, `$.fs`, `$.process`, `$.clock`, `$.tool`, `$.model`, `$.command`, ...).
  - `e` is the event input, frozen.
  - `next(e)` passes to the plugins beneath and then the engine's default. Returning without calling `next` overrides the default, and `next({ ...e, x })` rewrites what the rest of the chain sees.
- UI is JSX compiled against the global `h`. Get elements from the surface: `const { Box, Text, Button } = $.ui.resolve(e)`. `e.surface` is `terminal | desktop | vscode | mobile`, so don't assume terminal.
- Panes: open one with `$.ui.open({ id, title })` and draw it from `on('ui.render', { component: 'Pane', requestId: id }, ...)`. A pane opened unprompted (`session.start`, a timer) only seats at 144 or more terminal columns; one opened by user action seats at any width.
- Section titles: a bordered Box clips its children, so a border title is an absolute Box (`top={0}`) placed after the bordered Box inside an unbordered wrapper of the same size.
- Band above the prompt: `ui.render` on `{ component: 'AbovePrompt' }`. Status line: `$.ui.status(text)`. Toasts: `$.ui.toast(text)`.
- Commands: `$.command.register(...)` in `session.start`, handled by a `command.run` hook.
- Reactive state: `atom(ref, initial)`, `read($, atom)` while rendering, and `update($, atom, fn)` from handlers. Writes redraw the components that read the atom.
- Reload semantics: each reload re-runs `register` and fires `session.start` again. `$.state` (per session) and `$.store` (across sessions) persist; module-level variables reset. Keep anything that must survive a reload in `$.state` or `$.store`, and make `session.start` idempotent.
- A `ui.render` tree that fails validation is replaced by the engine's default rendering, with a dim transcript line `ide-panes: ui.render (<Component>) refused: <reason>`. Check that line first when UI doesn't appear.
- Write UI tests once and loop them over `['terminal', 'desktop'] as const`.

For any API detail, grep the generated `.claude-plugin/types/claude-code/index.d.ts` (or the skill's `claude-code.d.ts` before the first load) for the event or noun name, e.g. `'tool.call'`, `Pane: {`.

## Glossary

Use these names in code, comments, tests and chat.

- **Panel**: one whole IDE view, Explorer or Git (engine term: pane, `$.ui.open`, `component: 'Pane'`).
- **Main tabs**: the tab bar that switches between panels (Explorer, Git).
- **Section**: a named, bordered area inside a panel, e.g. Git's Branches, Commits, Info, Graph, Files, Diff Preview. Its name sits on its top border.
- **Panel tabs**: a panel's header tabs, switching its whole layout (Git: Overview / Graph / Change Log; Explorer: Files / Unity).
- **Header lines**: under the main tabs, each panel draws line 1 panel tabs (`header:tabs`), line 2 action Buttons (`header:actions`) and line 3 the interactive line (`header:ask`), drawn only while something asks: the question or name field on the left, its Buttons in the right corner. The sections' row budget counts the header lines drawn (2 or 3).
- **Diff view**: Git's full-panel Files | Diff Preview of one commit, opened from a commit row's `⧉` Button.
- **Edit section**: the Explorer's in-pane editor, standing in for Preview while a file is open for editing (`edit` or `new`); drawn by a `Client` (`editor-client.tsx`).
- **Splitter**: the draggable seam between two adjacent sections, a `Client` two cells across covering both frames' borders (grab either side), drawn last in the container holding both sections (terminal and desktop only).
- **Horizontal bar**: a one-row scrollbar (`━` thumb, `─` track) overlaid on a text section's bottom border while a line is wider than the room; dragged (a `Client`, `scrollbar-client.tsx` `axis: 'x'`; static Text without one) it scrolls the text sideways. A line scrolled past its end draws as `' '`, keeping its row. Lines are cut by column with `hooks/shared/hscroll.ts` (`widest`, `sliceCols`, `sliceDiffCols`: tabs expanded the way `Code` draws them, CJK/emoji 2 columns). Only Preview, Edit, Info and Diff Preview have one; list sections keep their fitted rows.
- Not "block": in `git.ts`, `block` means a diff file's header block.

## Features

- `/ide-panels` is the only command: it opens both panes as tabs (Explorer, Git), explorer in front.
- Explorer pane `ide-explorer` (`hooks/explorer-panel/`): sections `Files` (tree) and `Preview` (or the Edit section); `files` and `unity` modes, switched by the panel tabs `Files` (`f`) and `Unity` (`u`), with dim "not a Unity project" after them (Unity: `.meta` GUID references). Actions: `refresh`, `edit`, `new`, `delete`. The interactive line holds one of, by precedence: the conflict bar, the unsaved-changes bar, the delete bar, the `new` name field. Pure helpers in `tree.ts`, `unity.ts`, `editor.ts` (buffer, ops, keymaps), `edit.ts` (transfer protocol, draft paths).
  - Splitter `split:tree` between Files and Preview/Edit (default 0.35, at least 12 columns a side), fraction in `explorer.split.tree`; `view.treeEnd` (wheel routing, editor width) follows it. A release saves `$.store` `layout:explorer`; `session.start` loads it when the session has none.
  - Tree: labels are cut with `…` to the Files width (`fitLabel`, `tree.ts`), so a narrow Files never wraps a row. A press (click or Enter) selects a row; a press on the selected dir expands or collapses it. While editing, a dir press toggles at once (the selection stays on the edited file).
  - `edit` (previewed text file): the Edit section replaces Preview. Border Buttons `save`, `close`, `↑line`, `↓line`, `dup`, `del`; a `●` before `Edit` while unsaved.
  - `new`: an `Input` on the interactive line ("new file in <dir>/", `create`, a `cancel` Button); the dir is the selected dir, else the selected file's parent, else the root. `newFilePath` (`tree.ts`) refuses empty, absolute, `..`, trailing `/` and outside-root names; an existing path toasts. It opens the Edit section on an empty buffer (`edit.isNew`, counted as unsaved); the first save writes the file and its dirs.
  - `edit` and `new` only on terminal and desktop (they need a `Client`); vscode (has `Input`, no `Client`) and mobile draw neither.
  - `delete` (hotkey `d`, all surfaces; drawn when a row is selected and no conflict or unsaved bar is up): a red bar "Delete <name>? (N entries)" (dir, `find` count capped at `1000+`), "+ .meta" in unity mode when it exists, "(open in editor, unsaved)" when the dirty editor is in the target; `delete` / `cancel`. Permanent: `rm -rf --` the target (and `<path>.meta` in unity mode) through `$.process.run`, the explorer's only removal path besides drafts; `deleteTarget` (`tree.ts`) refuses the root, outside-root and odd segments. A failed rm toasts stderr's first line and changes nothing; success closes the editor if it was inside (draft removed), drops the target's, its parent's and its descendants' listings, `footers` and (unity) the GUID index, selects `afterDelete` (next sibling, else previous, else parent) and toasts `Deleted <name>`. Opening the bar closes the `new` field and vice versa.
  - Guards: one dirty check (`guarded`) puts up "Unsaved changes in X: save / discard / cancel" before selecting another file, `close`, a mode switch, `new`, or closing the pane (`ui.close` hook; only `unload` passes). A save whose file changed since load (or a new file's path now taken) asks "overwrite / reload / cancel"; Claude changing the open file (tool hooks) reloads a clean buffer and puts the bar over a dirty one.
  - Draft files: unsaved text is written ~1 s after typing to `~/.claude/ide-panes/drafts/<hash>.txt`; `session.start` bumps `edit.version`, and a draft newer than the file comes back. Save or discard removes it (`rm -f`).
  - Chunked load/save: text crosses between hook and client in 80k-char chunks (`TRANSFER_CHUNK`), each client message acked through props; files up to 4 MiB.
  - Horizontal bar `hb:preview` (`explorer.previewLeft`, reset with `previewOffset`; the Code gutter is digits of the last shown line + 2; total from all lines via `widthCache`) and `hb:edit`: the client owns `left` and sends `{ hview: { left, widest, width }, version }` when one changes (editor columns: a UTF-16 unit or a tab is one cell; the bar counts `widest + 1`, the caret's cell past the end); a drag sets `editing.hview.left` at once and sends the `left` command, which moves the view, not the cursor.
- Git pane `ide-git` (`hooks/git-panel/`), panel tabs:
  - Overview: Branches (under bold `▾ Local (N)` / `▾ Remote (N)` category rows, keys `l:` / `r:` in `git.collapsed`, both open by default; then grouped by `/`, remotes by remote name; the arrow is the Button, as a Button has no `bold`) | Commits over Info, two columns at every width. Commits draws one dot per commit (its lane color, `○` for merges). On terminal and desktop the dot, `>` marker and short sha are a `Client` column (`hooks/git-panel/dots-client.tsx`, key `dots`; Graph's is `shas`, lanes in their own column before it), each column painting the selected row's `SELECTED`: a left down/up on one row posts `{ press: y }` (`ui.message`: selects that commit, focuses its subject), and resting the pointer ~600 ms on a row's dot or sha (`{ hover: y }`, mapped through `commitWindow`) shows a card of the branches containing the commit (`git branch -a --contains`, `containsCache`) under bold `Local` and `Remote` headings (an empty group's left out), 4 names per group with its own `+N more`, 8 when the other is empty. Info: sha, author, date, parents, refs, the full `local` / `remote` lists of branches containing the commit (HEAD branch `*`, an empty one left out), message, `--stat` (no diff); scrolls on its own, sideways by `hb:info` (`git.infoLeft`).
  - Graph: full-width `Graph` (`git log --topo-order` with `%P`, one row per commit: colored lanes from `layoutGraph`, sha, refs, subject, author, date) over the selected commit's Info, seam `split:graph`. The same hover card on a sha, drawn in Graph's wrapper past the sha, flipped above its row when it would pass the seam.
  - Commit focus key `commit:<sha>`: the subject Button where the sha `Client` is drawn (terminal, desktop), else the sha Button (vscode, mobile; the subject is `subject:<sha>` there). Arrow keys, `autoFocus` and the `ui.focus` hook follow it.
  - Change Log: working tree vs HEAD as Files (`list` or `tree` view) | Diff Preview; the tab shows the change count. Diff Preview (here and in the diff view) scrolls sideways by `hb:details` (`git.detailLeft`): head lines by `sliceCols`, the windowed diff by `sliceDiffCols`, width from `diffGutter` + `widest(diffBody)` (`git.ts`).
  - Diff view: each commit row's `⧉` Button opens Files | Diff Preview for that commit (a merge against its first parent; `filesArgv`, `parseNameStatus`, `fileDiff` in `git.ts`); `back` or any tab closes it.
  - Splitters (Branches | right, Commits / Info, Graph / Info, Files | Diff Preview): `hooks/shared/splitter-client.tsx` (`span: 2`; `split:side` passes `marks` so Commits' `╰` and Info's `╭` corners stay), fractions in `git.split`, pure math in `hooks/shared/split.ts` (`splitAt`, `dragTo`, `layoutOf`). A drag's release saves the whole split to `$.store` `layout:git`; the render reads it once (module `storedLayout`, drawn as `state.split ?? storedLayout`) since a drawing may not write `$.state`.
  - Header lines: the tabs, then `back`, `refresh`, `fetch`, `pull`; no interactive line (nothing asks).
  - `fetch` (`git fetch --all`) and `pull` (`git pull --ff-only`) buttons; nothing else writes to the repo. The current branch also shows in the status line. Pure helpers in `git.ts`.
- Caches are module-level in each `index.tsx` (not `$.state`): explorer `listings`, `ignored`, `unityRoots`, GUID `indexes`, `footers` (branch + change counts per root), plus `editing` (the editor protocol's side, refilled after a reload), `naming` (the `new` field's dir), `widthCache` (Preview's widest line per path + mtime) and `deleteFacts` (the delete bar's kind, count and `.meta`); git `repoRoot`, `branchCache`, `statusCache`, `graphCache`, `showCache` (Info per sha), `diffCache` (files + patch per sha, diff view), `changeCache` (diff per path), `containsCache` (local and remote branches per sha, hover card and Info), `hasHead`, `storedLayout` (`layout:git`, read once), `diffWidth` (Diff Preview's width per diff string); transient: `hovered` (the card's sha), `commitWindow` (the shas as drawn and the key of the Client drawn for them, `dots` or `shas`; the Client's `y`).
- Footer (both panes): `~/path (branch)` left, `+added ~modified -deleted` right (dim when clean; untracked count as added). Explorer: no counts outside a repo; its `footers` is cleared with the listings by every hook and `refresh`.
- Cleared by: the `refresh` button (`r`) and each feature's `tool.call` hooks. Explorer: `Write`/`Edit`/`NotebookEdit` drop that file and its parent dir; `Bash` drops all listings (and the GUID index when the command matches `git|mv|rm|cp|unity`). Git: `Bash` clears all and re-reads the branch; `Write`/`Edit`/`NotebookEdit` drop the `git status` cache, `showCache` and `changeCache`; `diffCache` and `containsCache` are cleared only with everything (`refresh`, `Bash`, fetch, pull). The hooks never deny or rewrite a call.
- Hotkeys: `r` refresh (both), `f` Files tab, `u` Unity tab, `e` edit, `n` new, `d` delete (explorer); git: `o` Overview, `g` Graph, `c` Change Log, `f` fetch, `p` pull, `b` back (diff view only), `a` all branches, `d` diff (the selected commit row's `⧉`), `v` list/tree view (on Files' border).
- Editor keymap: JetBrains by default (ctrl+d duplicate, ctrl+y delete line, ctrl+shift+up/down move lines, ctrl+w extend selection, meta+j next occurrence, ctrl+s save, ctrl+z/ctrl+shift+z); the `vscode` preset swaps in its own. `userConfig` options (`plugin.json`, passed by `register.tsx` to the explorer): `editorKeymap` (`jetbrains` | `vscode`) and `editorKeys` (JSON of action to chord or chords, merged over the preset; bad entries toast once per load).
- Root: both panels take it from `$.session.root()` (stable when the shell `cd`s), not `session.cwd`.
- `$.state` atoms under `ide-panes`: `explorer` (`root`, `mode`, `expanded`, `selected`, `cursor`, `offset`, `previewOffset`, `previewLeft`, `deleting` (the delete bar's target), `split` (`tree`), `edit` (`path`, `baseMtime`, `isNew`, `hasDraft`, `version`, `conflict`, `confirm`, `pending`)) and `git` (`ref`, `selected`, `offset`, `limit`, `branchOffset`, `detailOffset`, `infoOffset`, `infoLeft`, `detailLeft`, `collapsed`, `tab` (`overview`/`graph`/`changelog`; an old `changes` reads as `changelog`), `change`, `changeOffset`, `changeView`, `changeCollapsed`, `diff`, `diffFile`, `diffFileOffset`, `split` (`side`, `info`, `files`, `graph`)). `$.store` keys: `explorer.mode:<root>` (the saved mode), `layout:explorer` (`{ tree }`) and `layout:git` (`{ side, info, files, graph }`), global section sizes.
- The explorer owns the plugin's only `session.start` hook and registers `/ide-panels`; git sets its status line on the first `prompt.submit` and after each `Bash` call.

## Validator constraints

- `hooks.json` `modules` takes one entry; a second is refused.
- One unmatched `session.start` hook per plugin; use a `{ tool }` matcher for each extra `tool.call` hook (one hook per tool per feature; the same `{ tool: 'Bash' }` in two features is accepted).
- `$` is followed only into functions declared in the same file, never across an import: keep `$`-using code in each feature's `index.tsx`, pure helpers in `.ts` files.
- Feature `register`s must be imported by name; no namespace import receiving `on`.
- Every `$.state` key must be declared in `types/index.d.ts`.
- Tests: the kit has no hotkey act; assert `props.hotkey` and press the Button by key.
